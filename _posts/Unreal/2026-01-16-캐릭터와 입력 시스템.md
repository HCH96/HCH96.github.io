## 액터(Actor)
액터는 언리얼 엔진의 월드에 배치되는 콘텐츠의 기본 단위이다.

- **컴포넌트의 컨테이너**: 액터는 그 자체로 기능을 수행하기보다, 여러 컴포넌트를 담고 관리하는 컨테이너 역할을 한다.
- **월드 인프라 활용**: 월드로부터 틱(Tick)과 시간 서비스(DeltaTime)를 제공받아 게임 로직을 실행하는 주체가 된다.
- **트랜스폼(Transform)의 위임**: 액터는 위치 정보를 직접 소유하지 않으며, 루트 컴포넌트로 지정된 컴포넌트의 좌표 정보를 자신의 위치로 사용한다.

### 컴포넌트(Component)
컴포넌트는 액터에 부착되어 실질적인 기능을 구현하는 부품이다.

- **USceneComponent**: 트랜스폼 정보를 소유하여 월드 내 좌표를 가질 수 있는 컴포넌트이다. 시각적 형태가 없는 상태로 존재하며 다른 컴포넌트의 기준점 역할을 수행한다.

- **루트 컴포넌트(Root Component)**: 액터에 반드시 하나 존재해야 하는 핵심 컴포넌트이다. 액터의 설계 목적에 따라 메시나 충돌체 등 다양한 컴포넌트가 루트가 될 수 있다.

- **월드 등록과 서비스**: 컴포넌트는 월드에 등록(Register)되어야만 틱(Tick)이나 렌더링 같은 월드 서비스를 정상적으로 제공받을 수 있다.

    - 생성자에서의 추가: `CreateDefaultSubObject`를 사용하여 생성자 단계에서 컴포넌트를 생성하며, 이는 클래스의 기본 프로퍼티로 포함되어 에디터에서 관리된다.

    - 런타임에서의 추가: 게임 실행 중에 동적으로 추가할 때는 `NewObject`로 생성한 후, 반드시 `RegisterComponent`를 호출하여 월드 시스템에 등록해야 한다.

- 계층 구조와 전파: 컴포넌트들은 트리 구조를 형성한다. 루트 컴포넌트의 트랜스폼 변화는 자식 컴포넌트들에게 상대적으로 전달되어 함께 움직이게 한다.

### 대표적인 컴포넌트 종류와 기능

- **UStaticMeshComponent**: 고정된 3D 모델을 표시하며 시각적 형태를 제공한다.
- **USkeletalMeshComponent**: 애니메이션이 필요한 액터 모델을 표시한다.
- **UCapsuleComponent / UBoxComponent**: 액터나 물체의 충돌 범위를 설정하고 물리 연산을 처리한다.
- **UCharacterMovementComponent**: 중력, 가속도, 마찰력 등 캐릭터의 복잡한 이동 로직을 담당한다.

### 컴포넌트 지정자와 에디터 활용

- Visible / Edit: 포인터로 관리되는 객체 타입에는 주로 `VisibleAnywhere`를 사용하며, 수치값과 같은 데이터 타입에는 `EditAnywhere`를 사용한다. `EditAnywhere`를 사용하면 포인터가 가리키는 객체 자체를 다른 것으로 변경할 수 있기 때문이다.
- Anywhere / DefaultsOnly / InstanceOnly: 에디터 디테일 패널 혹은 원본 에셋(Default) 등에서 편집 가능한 범위를 결정한다.
- BlueprintReadOnly / BlueprintReadWrite: 블루프린트에서 해당 컴포넌트를 참조만 할지, 혹은 런타임에 값을 변경할 수 있게 할지 권한을 부여한다.
- Category: 에디터 디테일 패널에서 컴포넌트와 변수들을 그룹화하여 관리 가독성을 높인다.

## 폰(Pawn)의 기능과 설계
폰은 플레이어가 빙의(Possess)하여 입출력을 처리할 수 있도록 설계된 특별한 액터이다.

- **빙의와 제어**: 플레이어 컨트롤러 또는 AI 컨트롤러가 빙의하여 제어권을 가질 수 있다.
- **길찾기 활용**: 일반 액터와 달리 내비게이션 시스템을 이용한 길찾기 기능을 기본적으로 사용할 수 있다.
- **핵심 구성**: 일반적으로 물리적 상호작용, 시각적 표현, 움직임 로직을 담당하는 세 가지 주요 컴포넌트로 구성된다.

### 폰의 내부 구성 및 계층 구조

- **UCapsuleComponent (루트 컴포넌트)**: 기믹과의 상호작용 및 물리 충돌을 담당하는 씬컴포넌트이다. 폰의 물리적 기준점 역할을 수행한다.
- **비주얼 컴포넌트 (Mesh)**: 폰의 시각적 형태를 담당하며, 애니메이션 필요 여부에 따라 두 클래스 중 하나를 선택한다.
    - **USkeletalMeshComponent**: 본(Bone) 구조를 포함한다. 뼈대를 이용한 정교한 애니메이션(캐릭터의 걷기, 공격 등)이 필요할 때 사용한다.
    - **UStaticMeshComponent**: 본이 없는 정적인 메시이다. 애니메이션이 필요 없는 배경 프롭이나 단순한 물체에 사용하며 연산 효율이 매우 높다.
- **UPawnMovementComponent**: 폰의 움직임 로직을 담당하는 컴포넌트이다. 트랜스폼 정보가 없는 액터컴포넌트(UActorComponent)로 설계된다.

## 캐릭터(Character)
캐릭터는 인간형 폰을 구성하도록 언리얼 엔진이 제공하는 전문 폰 클래스이다.

- 인간형 특화: 일반적인 폰 기능을 상속받으면서도, 이족 보행을 하는 인간형 개체에 필요한 복잡한 이동 로직이 사전에 구현되어 있다.
- 기본 컴포넌트 구성: 캡슐 컴포넌트(물리), 스켈레탈 메시 컴포넌트(비주얼), 캐릭터 무브먼트 컴포넌트(기능)의 세 가지 핵심 요소로 이루어진다.

### 캐릭터의 내부 구성
캐릭터 클래스는 폰의 추상적인 구성을 인간형 표준 모델에 맞춰 구체화한다.

- **UCapsuleComponent(루트 컴포넌트)**: 폰의 추상적인 충돌 기능을 '캡슐' 형태로 구체화하여 인간형 본체에 최적화된 충돌 판정을 제공한다. 캐릭터의 중심축 역할을 수행하며 다른 컴포넌트는 이 아래에 배치된다.
- **USkeletalMeshComponent**: 본(Bone) 애니메이션을 지원하는 메시 컴포넌트이다. 캐릭터의 부드러운 움직임과 외형을 표현한다.
- **UCharacterMovementComponent**: 캐릭터의 움직임을 담당하는 핵심 컴포넌트이다. 별도의 구현 없이도 걷기, 뛰기, 점프, 낙하, 수영 등 인간형 캐릭터의 모든 이동 물리 상태를 시스템적으로 지원한다.

## 입력 시스템의 동작 방식

플레이어의 하드웨어 입력은 컨트롤러를 거쳐 최종적으로 폰(Pawn)에게 전달된다.

- **입력 전달 경로**: 하드웨어 입력 -> 플레이어 컨트롤러(PlayerController) -> 폰(Pawn) 순으로 데이터가 흐른다.
- **처리 주체**: 입력을 컨트롤러에서 직접 처리할 수도 있고 폰이 처리하게 할 수도 있다. 일반적으로는 폰이 처리하도록 설정하는 것이 유지보수와 확장성 면에서 유리하다.
- **폰 처리의 장점**: 플레이어가 자동차, 비행기, 캐릭터 등 다양한 대상에 빙의(Possess)하는 게임의 경우, 각 폰이 자신만의 입력 처리 로직을 가지고 있으면 컨트롤러 코드를 복잡하게 수정하지 않아도 된다.


### 입력 시스템 계층 구조
입력은 우선순위에 따라 여러 단계를 거치며 처리된다.

- **InputComponent**: 액터가 입력을 받기 위해 가지는 컴포넌트이다.
- **우선순위 스택**: 입력 활성화된 액터 -> 플레이어 컨트롤러 -> 레벨 블루프린트 -> 폰 순서로 입력 기회를 가진다.
- **소비(Consume)**: 상위 계층에서 입력을 처리하고 '소비'해버리면 하위 계층까지 신호가 전달되지 않는다.

- **Enhanced Input**: 언리얼 엔진 5부터 표준이 된 시스템이다. 입력 매핑 컨텍스트(IMC)와 입력 액션(IA)을 분리하여 런타임에 입력 설정을 유연하게 교체할 수 있다.

## 향상된 입력 시스템(Enhanced Input)
기존의 단순 매핑 방식을 대체하여 사용자 입력 설정 변경에 유연하게 대처할 수 있는 구조를 가진 입력 시스템이다.

- **데이터 기반 구조**: 사용자의 입력 처리를 네 단계로 세분화하고 각 설정을 독립적인 애셋으로 대체하여 관리한다.
- **동적 변경**: 게임 플레이 도중 상황(예: UI 오픈, 탑승 등)에 따라 입력 매핑 컨텍스트를 즉시 교체할 수 있다.

### 향상된 입력 시스템 동작 구성
사용자 입력 데이터를 최종 함수에 매핑하는 과정은 다음과 같은 요소들로 구성된다.

- **입력 매핑 컨텍스트(Input Mapping Context)**: 사용자 입력(키보드, 패드 등)을 특정 입력 액션과 연결한다. 상황에 따라 컨텍스트를 동적으로 교체할 수 있다.
- **입력 액션(Input Action)**: '점프'나 '이동'처럼 추상화된 입력의 단위이다.
- **수정기(Modifier)**: 입력 데이터 값을 최종 전달 전 변조한다. (예: 축 반전, Deadzone 설정 등)
- **트리거(Trigger)**: 이벤트가 발생하기 위한 세부 조건을 결정한다. (예: 누르고 있기, 두 번 누르기 등)

### 향상된 입력 시스템의 장점

- 유연한 플랫폼 대응: 키보드용 IMC와 게임패드용 IMC를 별도로 제작하여, 연결된 장치에 따라 실시간으로 최적화된 매핑을 제공할 수 있다.
- 입력 데이터의 추상화: InputAction은 실제 키가 무엇인지 몰라도 된다. 점프라는 액션만 정의해두면, 에디터에서 스페이스바든 패드 A버튼이든 자유롭게 연결 가능하다.

## 실습

### ABGameMode
```cpp
#include "Game/ABGameMode.h"
#include "ABGameMode.h"

AABGameMode::AABGameMode()
{

	static ConstructorHelpers::FClassFinder<APawn> DefaultPawnClassRef(TEXT("/Script/ArenaBattle.ABCharacterPlayer"));
	if (DefaultPawnClassRef.Class)
	{
		DefaultPawnClass = DefaultPawnClassRef.Class;
	}

	static ConstructorHelpers::FClassFinder<APlayerController> PlayerControllerClassRef(TEXT("/Script/ArenaBattle.ABPlayerController"));
	if (PlayerControllerClassRef.Class)
	{
		PlayerControllerClass = PlayerControllerClassRef.Class;
	}
}
```

- GameMode를 상속 받은 ABGameMode 클래스의 생성자에서 DefaultPawnClass와 PlayerControllerClass를 지정한다. 
- 지정할 때는 의존성을 줄이기 위해 ConstructorHelpers와 래퍼런스 정보를 이용해 클래스의 정보를 가져온다.

#include "Character/ABCharacterBase.h"

	// Pawn
	bUseControllerRotationPitch = false;
	bUseControllerRotationYaw = false;
	bUseControllerRotationRoll = false;

	GetCapsuleComponent()->InitCapsuleSize(42.f, 96.0f);

	// Movement

	GetCharacterMovement()->MinAnalogWalkSpeed = 20.f;
	GetCharacterMovement()->BrakingDecelerationWalking = 2000.f;

	// Mesh
	GetMesh()->SetRelativeLocationAndRotation(FVector(0.0f, 0.0f, -100.0f), FRotator(0.0f, -90.0f, 0.0f));
	GetMesh()->SetAnimationMode(EAnimationMode::AnimationBlueprint);
	GetMesh()->SetCollisionProfileName(TEXT("CharacterMesh"));

	static ConstructorHelpers::FObjectFinder<USkeletalMesh> CharacterMeshRef(TEXT("/Script/Engine.SkeletalMesh'/Game/Characters/Mannequins/Meshes/SKM_Quinn_Simple.SKM_Quinn_Simple'"));

		GetMesh()->SetSkeletalMesh(CharacterMeshRef.Object);

	static ConstructorHelpers::FClassFinder<UAnimInstance> AnimInstanceClassRef(TEXT("/Game/Characters/Mannequins/Animations/ABP_Quinn.ABP_Quinn_C"));

		GetMesh()->SetAnimInstanceClass(AnimInstanceClassRef.Class);
	}
}

### ABCharacterPlayer

```cpp
#include "Character/ABCharacterPlayer.h"
#include "Camera/CameraComponent.h"
#include "GameFramework/SpringArmComponent.h"
#include "InputMappingContext.h"
#include "EnhancedInputComponent.h"
#include "EnhancedInputSubsystems.h"

AABCharacterPlayer::AABCharacterPlayer()
{
	// Camera
	CameraBoom = CreateDefaultSubobject<USpringArmComponent>(TEXT("CameraBoom"));
	CameraBoom->SetupAttachment(RootComponent);
	CameraBoom->TargetArmLength = 400.0f;
	CameraBoom->bUsePawnControlRotation = true;

	FollowCamera = CreateDefaultSubobject<UCameraComponent>(TEXT("FollowCamera"));
	FollowCamera->SetupAttachment(CameraBoom, USpringArmComponent::SocketName);
	FollowCamera->bUsePawnControlRotation = false;

	// Input
	static ConstructorHelpers::FObjectFinder<UInputMappingContext> InputMappingContextRef(TEXT("/Script/EnhancedInput.InputMappingContext'/Game/ArenaBattle/Input/IMC_Default.IMC_Default'"));
	if (nullptr != InputMappingContextRef.Object)
	{
		DefaultMappingContext = InputMappingContextRef.Object;
	}

	static ConstructorHelpers::FObjectFinder<UInputAction> InputActionMoveRef(TEXT("/Script/EnhancedInput.InputAction'/Game/ArenaBattle/Input/Actions/IA_Move.IA_Move'"));
	if (nullptr != InputActionMoveRef.Object)
	{
		MoveAction = InputActionMoveRef.Object;
	}

	static ConstructorHelpers::FObjectFinder<UInputAction> InputActionJumpRef(TEXT("/Script/EnhancedInput.InputAction'/Game/ArenaBattle/Input/Actions/IA_Jump.IA_Jump'"));
	if (nullptr != InputActionJumpRef.Object)
	{
		JumpAction = InputActionJumpRef.Object;
	}

	static ConstructorHelpers::FObjectFinder<UInputAction> InputActionLookRef(TEXT("/Script/EnhancedInput.InputAction'/Game/ArenaBattle/Input/Actions/IA_Look.IA_Look'"));
	if (nullptr != InputActionLookRef.Object)
	{
		LookAction = InputActionLookRef.Object;
	}
}

void AABCharacterPlayer::BeginPlay()
{
	Super::BeginPlay();

	APlayerController* PlayerController = CastChecked<APlayerController>(GetController());
	if (UEnhancedInputLocalPlayerSubsystem* Subsystem = ULocalPlayer::GetSubsystem<UEnhancedInputLocalPlayerSubsystem>(PlayerController->GetLocalPlayer()))
	{
		Subsystem->AddMappingContext(DefaultMappingContext, 0);
		//Subsystem->RemoveMappingContext(DefaultMappingContext);
	}

}

void AABCharacterPlayer::SetupPlayerInputComponent(class UInputComponent* PlayerInputComponent)
{
	Super::SetupPlayerInputComponent(PlayerInputComponent);

	UEnhancedInputComponent* EnhancedInputComponent = CastChecked<UEnhancedInputComponent>(PlayerInputComponent);

	EnhancedInputComponent->BindAction(JumpAction, ETriggerEvent::Triggered, this, &ACharacter::Jump);
	EnhancedInputComponent->BindAction(JumpAction, ETriggerEvent::Completed, this, &ACharacter::StopJumping);
	EnhancedInputComponent->BindAction(MoveAction, ETriggerEvent::Triggered, this, &AABCharacterPlayer::Move);
	EnhancedInputComponent->BindAction(LookAction, ETriggerEvent::Triggered, this, &AABCharacterPlayer::Look);
}

void AABCharacterPlayer::Move(const FInputActionValue& Value)
{
	FVector2D MovementVector = Value.Get<FVector2D>();

	const FRotator Rotation = Controller->GetControlRotation();
	const FRotator YawRotation(0, Rotation.Yaw, 0);

	const FVector ForwardDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::X);
	const FVector RightDirection = FRotationMatrix(YawRotation).GetUnitAxis(EAxis::Y);

	AddMovementInput(ForwardDirection, MovementVector.X);
	AddMovementInput(RightDirection, MovementVector.Y);
}

void AABCharacterPlayer::Look(const FInputActionValue& Value)
{
	FVector2D LookAxisVector = Value.Get<FVector2D>();

	AddControllerYawInput(LookAxisVector.X);
}
```

- ABCharacterPlayer 클래스는 ABCharacterBase클래스를 상속받아 카메라의 관련된 설정과 입력을 처리 로직을 구현한다.
- 카메라는 플레이어에게만 존재하는 기능이기 때문에 ABCharacterBase가 아닌 ABCharacterPlayer에서 구현한다.
- BeginPlay시점에 에셋으로 저장해둔 InputMappingContext를 플레이어 컨트롤러에 추가한다.
- SetupPlayerInputComponent 함수에서 입력 액션과 이벤트를 바인딩한다.
- Move 함수에서 입력값을 받아 캐릭터를 이동시킨다.
- Look 함수에서 입력값을 받아 캐릭터를 회전시킨다.
- Move, Look 함수는 실제 입력과는 상관없이 추상화된 입력값을 받아 처리하기 때문에 나중에 키보드가 아닌 다른 입력장치를 사용하더라도 함수 내부의 로직은 변경할 필요가 없다.
- 입력 매핑은 에셋의 형식으로 저장되기 때문에, 에디터에서 키보드, 게임패드, 모바일 등 다양한 입력장치에 대한 매핑을 쉽게 변경할 수 있다.
