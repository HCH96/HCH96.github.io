## 애니메이션
언리얼 엔진의 애니메이션 시스템은 캐릭터의 시각적 실체인 **스켈레탈 메시(Skeletal Mesh)**에 이를 제어하는 로직 객체인 **애님 인스턴스(AnimInstance)**를 결합하여 동작한다. 애님 인스턴스는 캐릭터의 속도나 상태값 같은 게임 데이터를 실시간으로 가져와 업데이트하는 역할을 수행하며, 스켈레탈 메시에서는 사용할 애님 인스턴스 클래스와 애니메이션 모드를 설정하여 최종적으로 캐릭터가 취해야 할 애니메이션 포즈를 결정한다.

### AnimInstance 클래스
애님 인스턴스는 스켈레탈 메시 컴포넌트에 귀속되어 게임의 논리적 상태를 애니메이션 시스템으로 전달하는 핵심 객체이다. 캐릭터의 물리적 변화를 실시간으로 감지하여 애니메이션 블루프린트(ABP)가 적절한 동작을 수행할 수 있도록 데이터를 제공한다.

#### 특징
- 데이터 브릿지: C++ 클래스(UAnimInstance) 수준에서 폰(Pawn)의 이동 속도나 낙하 여부 등 게임 로직에 필요한 물리 데이터를 쿼리하여 변수로 관리한다. 이 데이터들은 애님 그래프(AnimGraph) 내에서 현재 어떤 애니메이션을 재생할지, 혹은 어떻게 포즈를 섞을지 결정하는데 사용된다.

- 상태 동기화: 스켈레탈 메시 컴포넌트가 업데이트 신호를 보내면, 애님 인스턴스는 NativeUpdateAnimation을 통해 월드의 최신 캐릭터 상태를 애니메이션 시스템에 동기화해주는 역할을 수행한다.

#### AnimInstance의 초기화와 데이터 참조
AnimInstance는 캐릭터(Actor)가 생성될 때 함께 객체화되어 메시 컴포넌트에 장착된다. 이때 액터와 AnimInstance는 서로를 참조할 수 있는 인터페이스를 제공하는데, 이 과정에서 객체 간의 초기화 순서와 데이터 접근의 안전성을 고려하는 것이 중요하다.

- 참조 구조
  액터는 GetAnimInstance()를 통해 자신이 소유한 메시의 애님 인스턴스에 접근할 수 있으며, 반대로 애님 인스턴스는 GetOwningActor()를 통해 자신을 소유한 액터의 정보에 접근할 수 있다.

- 초기화 순서와 위험성
  캐릭터가 초기화되는 시점에 애님 인스턴스 객체가 생성되지만, GetOwningActor()를 통해 액터의 로직을 직접 참조하는 것은 위험할 수 있다. 게임 엔진의 업데이트 순서에 따라 애님 인스턴스가 액터보다 먼저 실행되거나, 액터가 아직 완전히 유효하지 않은(Null) 상태에서 데이터에 접근하려 할 경우 크래시가 발생할 가능성이 높기 때문이다.

- 동기화 함수
  - NativeInitializeAnimation: 애님 인스턴스가 생성된 후 단 한 번 호출되는 초기화 함수이다. 일반 액터의 BeginPlay와 유사하며, 여기에서 폰이나 무브먼트 컴포넌트를 미리 캐싱해둠으로써 매 프레임 발생하는 불필요한 연산 비용을 절감할 수 있다.

  - NativeUpdateAnimation: 매 프레임마다 호출되어 캐릭터의 최신 물리 데이터를 업데이트하는 함수이다. TryGetPawnOwner()와 같은 안전한 접근 함수를 사용하여 액터의 유효성을 매번 검사하며 데이터를 가져오기 때문에, GetOwningActor()를 직접 사용하는 것보다 훨씬 안전하게 게임 로직과 애니메이션 시스템을 동기화할 수 있다.

### 애니메이션 블루프린트 (Animation Blueprint)
애니메이션 블루프린트(ABP)는 AnimInstance의 로직을 시각적으로 구성한 에셋이다. 단순히 애니메이션을 재생하는 것을 넘어, 캐릭터의 상태에 따라 복잡한 포즈 연산을 수행하는 그래프 기반의 제어 도구이다.

#### 특징

- 스켈레톤(Skeleton) 호환성: ABP는 생성 시점에 반드시 특정 스켈레톤 설계도와 연결되어야 한다. 이는 해당 스켈레톤이 가진 본(Bone)의 계층 구조와 명칭 정보를 ABP가 인식하기 위함이다. 만약 캐릭터 메시에 설정된 스켈레톤과 ABP가 참조하는 스켈레톤이 일치하지 않을 경우, 데이터가 달라 본 트랜스폼을 계산할 수 없으므로 캐릭터가 T-Pose로 고정되는 등 애니메이션이 정상적으로 출력되지 않는다.

- 이벤트 그래프(Event Graph): 게임 로직으로부터 필요한 데이터를 수집하고 가공하는 공간이다. NativeUpdateAnimation과 같은 업데이트 이벤트를 통해 폰의 속도, 가속도, 상태값 등을 받아와 변수에 저장하는 역할을 한다.

- 애님 그래프(AnimGraph): 이벤트 그래프에서 준비한 데이터를 바탕으로 실제 캐릭터의 포즈를 결정하는 공간이다. State Machine을 통해 애니메이션을 전환하거나, 여러 애니메이션을 섞는 블렌딩(Blending), 본의 위치를 직접 수정하는 로직 등을 실행한다. 결과적으로 매 프레임 캐릭터가 취해야 할 최종 포즈를 산출하여 출력한다.

#### 주요 노드

1. 스테이트 머신 (State Machine)
캐릭터의 논리적 상태(Idle, Walk, Run, Jump 등)를 구분하고 관리하는 컨트롤 타워이다. 현재 캐릭터의 속도나 공중 부양 여부 같은 물리 값을 실시간으로 체크하여, 현재 상태를 유지할지 아니면 다른 상태로 넘어갈지를 판단한다. 각 상태는 독립적인 애니메이션 에셋을 출력하며, 캐릭터의 전체적인 동작 흐름을 설계하는 기반이 된다.

2. 스테이트 에일리어스 (State Alias)
점프나 피격처럼 여러 상태에서 공통적으로 발생하는 전이 조건을 한곳에 묶어 관리하는 가상 상태 노드이다. 기존 방식대로라면 모든 상태에서 각각 전이 화살표를 뽑아 그래프가 거미줄처럼 복잡해지지만, 에일리어스를 활용하면 체크박스 설정만으로 전이 경로를 단순화할 수 있어 가독성이 좋아진다.

3. 트랜지션 (Transition)
상태와 상태 사이를 잇는 통로로, 실제 애니메이션이 교체되는 시점과 방식을 정의한다. 내부의 전이 규칙에 작성된 불리언(Boolean) 조건이 충족되면 전환이 시작되며, 이때 블렌딩 설정을 통해 두 포즈가 섞이는 시간이나 커브 종류를 조절하여 시각적인 어색함 없이 부드러운 동작 연결을 만들어낸다.

4. 포즈 캐싱 (Pose Caching / Saved Cached Pose)
복잡한 노드 망을 거쳐 완성된 특정 포즈를 변수처럼 임시 저장하여 재사용하는 최적화 도구이다. 하체 걷기 포즈처럼 그래프 내 여러 곳에서 중복으로 필요한 연산이 있을 때, 매번 다시 계산하지 않고 캐시된 결과값을 이름으로 불러와 사용한다.
