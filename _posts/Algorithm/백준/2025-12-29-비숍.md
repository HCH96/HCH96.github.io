## code

### 시간초과
```cpp
#include <iostream>
#include <bits/stdc++.h>
#include <sstream>

using namespace std;

int N, Answer;

vector<vector<int>> Board;
unordered_map<int, bool> Left;
unordered_map<int, bool> Right;


bool Check(int Row, int Col)
{
    int RightIdx = Row + Col;
    int LeftIdx = Row - Col + N - 1;

    return !(Right[RightIdx] || Left[LeftIdx]);
}

void Mark(int Row, int Col, bool Flag)
{
    int RightIdx = Row + Col;
    int LeftIdx = Row - Col + N - 1;

    Right[RightIdx] = Flag;
    Left[LeftIdx] = Flag;
}

void Sol(int Idx, int Count)
{
    Answer = max(Answer, Count);

    for (int i = Idx; i < 2 * N - 1; ++i)
    {
        int StartRow = min(i, N - 1);
        int StartCol = max(0, i - (N - 1));

        int Diff = StartRow - StartCol;

        for (int j = 0; j <= Diff; ++j)
        {
            int Row = StartRow - j;
            int Col = StartCol + j;

            if (Board[Row][Col] == 1 && Check(Row, Col))
            {
                Board[Row][Col] = 0;
                Mark(Row, Col, true);
                Sol(i + 1, Count + 1);
                Mark(Row, Col, false);
                Board[Row][Col] = 1;
            }
        }
    }

}


int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    cin >> N;

    Board.resize(N, vector<int>(N));

    for (int i = 0; i < N; ++i)
    {
        for (int j = 0; j < N; ++j)
        {
            cin >> Board[i][j];
        }
    }

    Sol(0, 0);

    cout << Answer;

    return 0;
}
```

    if (IsWhite)
    {
        WhiteMax = max(WhiteMax, Count);

## 문제 개요

N×N 체스판이 주어지고, 일부 칸에는 비숍을 놓을 수 있고(1), 일부 칸에는 놓을 수 없다(0).  
비숍은 **대각선 방향으로만 이동**하며, 서로 공격하지 않게 **최대 몇 개의 비숍**을 놓을 수 있는지를 구하는 문제이다.

- 가로 / 세로는 전혀 상관 없음
- 충돌 조건은 **두 종류의 대각선**뿐
  - 좌상 → 우하 (`\`)
  - 우상 → 좌하 (`/`)
- N ≤ 10

---

## 1. 완전 탐색

처음에는 자연스럽게 N-Queen과 비슷하게 생각했다.

- 각 칸에 대해  
  - 놓는다 / 안 놓는다
- 비숍은 대각선만 체크하면 되니까  
  → 두 개의 대각선 visited 배열로 O(1) 체크 가능

하지만 이 방식은 금방 한계에 부딪힌다.

- 최대 100칸
- 각 칸마다 선택/비선택 → 경우의 수가 기하급수적으로 증가
- 체크가 O(1)이어도 **탐색 공간 자체가 너무 큼**

즉, 단순히 체크를 빠르게 하는 것만으로는 시간 초과를 피할 수 없다.

---

## 2. 대각선 단위 탐색으로 개선

비숍의 중요한 성질 하나:

- **한 대각선에는 최대 하나의 비숍만 놓을 수 있다**

그래서 탐색 단위를 “칸”이 아니라 **“대각선”**으로 바꾸는 아이디어를 떠올릴 수 있다.

- 한 방향(`\`) 대각선을 기준으로
- 대각선마다
  - 그 위에 놓을 수 있는 칸 중 하나를 선택

이렇게 하면 탐색 깊이는 최대 `2N-1`로 줄어든다.

하지만 이것만으로는 여전히 시간 초과가 발생한다.

---

## 3. 체스판 색깔 분리

비숍은 자신의 시작 칸 색깔을 절대 벗어나지 못한다는 성질이 있다. 즉, 흰색 비숍은 흰색 칸위에만 존재할 수 있으며, 검은색 칸 비숍은 검은색 칸 위에만 존재할 수 있다.

- 흰색 칸에 있는 비숍은 흰색 칸으로만 이동
- 검은색 칸에 있는 비숍은 검은색 칸으로만 이동

이 말은 곧,
- 흰색 칸에 놓는 비숍들끼리는 서로 영향이 있고
- 검은색 칸에 놓는 비숍들끼리는 서로 영향이 있지만
- **흰색과 검은색은 서로 완전히 독립**이라는 뜻이다.

---

## 4. 기존 탐색의 비효율

대각선을 0 → 1 → 2 → … 순서로 탐색하면 이런 일이 벌어진다.

- 0번 대각선: 흰색 칸
- 1번 대각선: 검은색 칸
- 2번 대각선: 흰색 칸
- 3번 대각선: 검은색 칸
- …

즉, 하나의 DFS 트리 안에서

- 흰색 선택 × 검은색 선택이 **서로 곱해지면서** 탐색된다.

하지만 실제로는

- 흰색 칸에서의 최적 배치는
- 검은색 칸 선택과 **전혀 무관**하다.

그래서 흰색/검은색을 섞어서 한 번에 탐색하면
**불필요한 경우의 수가 폭발**하게 된다.

---

## 5. 해결 전략 – 문제를 두 개로 분리

문제를 다음 두 개로 완전히 분리한다.

1. **흰색 칸에만 비숍을 놓는 문제**
2. **검은색 칸에만 비숍을 놓는 문제**

그리고 각각 독립적으로 최댓값을 구한 뒤, 두 최댓값을 합산하여 최종 답을 구한다.

- 최종 답 = 흰색 최대 + 검은색 최대

---

## 6. 대각선 단계 DFS 구조

색깔을 분리한 뒤에도 탐색은 대각선 기준으로 진행한다.

중요한 점은:

- **한 재귀 호출이 하나의 대각선만 처리**해야 한다는 것

각 대각선에서 선택지는 두 가지뿐이다.

1. 이 대각선에는 **아무 것도 놓지 않는다**
2. 이 대각선 위의 가능한 칸 중 **하나를 골라 놓는다**

이렇게 하면 탐색 구조가 깔끔한 DFS가 된다.
